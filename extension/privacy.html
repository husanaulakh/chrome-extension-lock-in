Lock inGuide ↗

Your records stay with you.

Lock in has no account, advertising, telemetry, remote code, or data server. It does not transmit your browsing records.

What is stored

Regular sessions store the task name, chosen focus URL, resource rules, blocked domains, timestamps, time extensions, temporary permission domains, and domain-level distraction attempts in this browser profile. Full focus URLs can include document IDs or query values. Access and exit reasons are validated but not retained.

Up to 100 sessions and 2,000 observed attempts per session are kept. Reports count retained observations and may count block-page reloads again. They are not a full browsing audit.

Private browsing

Private navigation attempts are never added to reports. Sessions started in private windows use temporary browser storage and temporary network rules, with no history entry. Closing the browser clears them. Regular sessions remain regular sessions when used from a private window; intentional changes to their allowed resources remain in that saved session.

Permission purpose

Storage preserves session state. Alarms schedule expiry. Tabs and webNavigation identify destinations and route changes. Declarative network rules redirect disallowed top-level HTTP(S) pages. Host permissions allow redirects on the sites you choose. Page contents, keyboard input, passwords, and cookies are not read.

The blocked destination is temporarily held in the block page’s URL fragment so an approved access request can return there. Its path and query are not saved in attempt statistics.

Your controls

Export a JSON backup or delete history from Dashboard. Exported files may contain personal task names and focus URLs. Removing the extension clears its browser storage. There is no cloud backup or sync.

Private-window permission is off until you enable it in the browser. Browser vendors may collect their own diagnostics, which are outside this extension’s control.

Firefox private-session limit

Firefox private sessions are unavailable in 0.2.1 because its shared background context cannot isolate them from normal windows. Regular sessions can cover private windows with permission; private attempts remain excluded. Chromium private sessions retain their existing temporary-storage behavior.
